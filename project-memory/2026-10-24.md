## 五、教训：复读机故障三连

| 次 | 症状 | 根因 | 处置 |
|---|---|---|---|
| 一 | 一条消息重复发 ~15 个相同 compress | 首个参数 `summary: null` 被拒，错误提示「re-issue」，原样照抄没修正 | 喊停后改用修复性压缩，块 ID 无重复无损坏 |
| 二 | 一条消息重复发数百个 edit | 生成退化循环（同类成因） | 自检零损坏（版本/3 处新代码均未落盘），改「一次生成、一个脚本落盘」 |
| 三 | 落盘脚本 write 报成功但全盘零命中 | 同一条消息 write 发两遍且第二遍标签损坏，规范那次被连累作废 | 换名重写 _t015_apply2.js，先 `test -f` + `node --check` 验证再执行 |

**流程铁律（已验证）**：改动只生成一次 → 一个脚本统一落盘（锚点必须恰好出现 1 次，全过才写盘）→ 立刻 grep / node --check 校验；单条消息 tool 调用 ≤3 个。

### 三个 bug（全是 v4.29.0 埋的，全在流水线自己身上，与网络无关）

| # | 毛病 | 白话解释 | 修法 |
|---|---|---|---|
| 1 | 段号只升不退 | 点「下一段」先把段号加一；失败后重试被当成要跳下一段 → 没初稿被拦 → 再点再跳 → 3 次后段号顶到 4 且不回退，**按钮永久失灵** | 段号由已完成内容推导（`!PL.draft ? 1 : (!PL.critique ? 2 : 3)`），`PL.stage` 只在 `plRun` 真正跑完才推进 |
| 2 | 关弹窗后 running 没清 | 跑到一半关弹窗，程序还记着「正在跑」，重开后 `if(PL.running) return` 把一切拦截 | `pl-close` 改为取消本段（cancel + abort + 清 running/ctrl），`plOpen` 重开时先掐掉残留调用再重置 |
| 3 | 中断按钮按了不断 | 只改内部记号，fetch 要等 CFG.timeout（默认 180 秒）才 abort → 感觉像死机 | `callModelSimple` 加第 4 参 `extSignal`，`PL.ctrl` 作运行凭证，中断/关闭立即 abort；`finally` 只在 `PL.ctrl===ctrl` 时清 running（避免污染新一轮）；主动中断不再算失败 |
