## 一、抄了哪些「大神作业」

### 1.1 GitHub 开源工具取经

扒了十几个翻译 / 校对 / 审校领域的开源工具，每个只取它**最值钱的那一招**：

| 工具（GitHub） | 最值钱的一招 | 状态 |
|---|---|---|
| **AiProofAgent** | 一校 / 二校分离：先抓硬伤，再精修文风 | ✅ v4.9.0 |
| **TranslationCorrect** | 错误高亮 + 分类标注 | ✅ v4.9.0 |
| **translate5** | 修订追踪 TrackChanges + 术语 QA | ✅ v4.23.0（导回 Word 修订模式）|
| **Aphra** | 翻译→批评→精修 三段式流水线 + 联网查证 | ✅ 查证 v4.19.0 / ❌ 三段式 |
| **OpenTranslator** | 专人管术语一致性的「校验员」 | ✅ v4.8.0 |
| **repo-translator** | AI 抽样质检（不全文复查，省成本） | ❌ 未采纳 |
| **OmegaT** | 翻译记忆：校过的句子直接复用 | ✅ v4.14.0 完全匹配 / ✅ v4.23.0 模糊匹配 |
| **qe4pe / divemt** | 质量预估：先告诉你译文「有多难改」 | ✅ v4.18.0 |

**一句话总结共同规律**：高手们都不满足于「AI 改完给你看」，而是围绕三件事做文章——
1. 让错误「看得见、归得类」（高亮 + 分类）；
2. 让校对「分阶段、可回退」（一校二校、修订留痕）；
3. 让重复劳动「零成本复用」（翻译记忆、术语一致性体检）。

### 1.2 BelinDoc 取经（2026-10）

朋友推荐的「AI 文档翻译」工具（belindoc.com）。它跟我们**不是一类**——它是「上传文档 → 全文翻译 → 保持格式导出」，我们是「译校助手」（校对已有译文 + 术语一致）。三点可取：

| BelinDoc 的做法 | 对我们有什么用 | 状态 |
|---|---|---|
| **格式保持 / 版式还原**（翻译完导回 Word） | 校对完导回原文档，改动以 Word 修订痕迹标出，逐条接受/拒绝 | ✅ v4.23.0（修订模式）|
| **多模型预设下拉**（GPT/Claude/Gemini/DeepSeek） | 24 家一键切换，选中即回填接口地址与模型名（含小米 MiMo）| ✅ v4.23.0 |
| **首页「效果演示」**（真实对比图） | 「使用指南」加示例 + 校对前后对比 | ❌ 待做（P3）|

**它的护城河缺口 = 我们的护城河**：它没有术语库、没有术语一致性体检、没有决策面板、没有校对流程，只"翻"不"校"，术语必然不统一——这正是我们的核心价值，别丢。

### 1.3 新一轮取经：校对质量 + 人机分工（2026-10-13）

用户核心关切：「AI 究竟不是人，不能把所有工作都交给工具处理，这可能会丧失文本原有的一层含义，造成学术不严谨与误读」——本轮取经都围绕**「AI 提议、人拍板」**原则（AI 只举手报告，不擅自改写）。

| 参考来源 | 借来的一招 | 拟做功能 | 状态 |
|---|---|---|---|
| **nlprule**（GitHub，Rust 规则引擎）| 先用本地规则抓「确定性错误」，零 token，LLM 只管难的 | 本地规则预筛层（重复标点/双空格/数字单位混排等正则先抓） | ❌ 待做 |
| **Whispering-LLaMA / buzz**（ASR 纠错方向）| AI 对每句自报把握度，低把握全部标给人工 | 置信度分层审校（低把握句全标出，高把握抽样） | ❌ 待做 |
| **用户提议（2026-10-13）** | 标出歧义/多义/可读性差的极难句（含 ASR 乱码），给可选译法、可编辑、可自行翻译，完成后纳入译文 | **疑难句标注 + 可选译法卡片**（放校对栏目） | ✅ v4.24.0 |
| **用户提议（2026-10-13）** | 文本排序整理、段落还原、去 ASR 噪声 | **原文/译文整理**（校对前前置按钮，Ctrl+Z 可撤销） | ✅ v4.24.0 |
| **memoQ/Xbench 式 QA 类别**（既有笔记延伸）| 数字、日期、单位、专名一致性检查 | 数字/专名一致性本地体检（术语体检姊妹篇，零 token） | ❌ 待做 |
| **Aphra 三段式**（既有笔记）| 批评环节 = 疑难标注的另一种排法 | 三段流水线（翻译→批评→精修），与疑难标注合并考虑 | ❌ 待做（P2，既有）|

备注：2026-10-13 本轮 web_search 端点欠费（DeepSeek 402），公开搜索引擎不可用；GitHub 官方 API 可用，已扫 proofreading/NLP/ASR 纠错 topic。如需更深爬取需给搜索端点充值或换端点（设置 → 插件 → Web search）。

## 三、如果只先做三件事（Top 3）

1. 🥈 **修订对照三栏逐句视图** —— 改动片段已能看，但逐句对齐（原文|原译|修订）读起来更顺，是现有 🟡 半成品的自然升级。
2. 🥈 **三段流水线（翻译→批评→精修）** —— 三次调用串起来自动多轮打磨，复用现有 callModel。
3. 🥉 **使用指南加「效果演示」** —— 纯前端示例对比图，新用户一看就懂。

三者都**不碰后端、不动架构**，符合「实用、最常用、不花里胡哨」。
