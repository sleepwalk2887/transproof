## 一、抄了哪些「大神作业」

### 1.1 GitHub 开源工具取经

扒了十几个翻译 / 校对 / 审校领域的开源工具，每个只取它**最值钱的那一招**：

| 工具（GitHub） | 最值钱的一招 | 状态 |
|---|---|---|
| **AiProofAgent** | 一校 / 二校分离：先抓硬伤，再精修文风 | ✅ v4.9.0 |
| **TranslationCorrect** | 错误高亮 + 分类标注 | ✅ v4.9.0 |
| **translate5** | 修订追踪 TrackChanges + 术语 QA | ✅ v4.23.0（导回 Word 修订模式）|
| **Aphra** | 翻译→批评→精修 三段式流水线 + 联网查证 | ✅ 查证 v4.19.0 / ❌ 三段式 |
| **OpenTranslator** | 专人管术语一致性的「校验员」 | ✅ v4.8.0 |
| **repo-translator** | AI 抽样质检（不全文复查，省成本） | ❌ 未采纳 |
| **OmegaT** | 翻译记忆：校过的句子直接复用 | ✅ v4.14.0 完全匹配 / ✅ v4.23.0 模糊匹配 |
| **qe4pe / divemt** | 质量预估：先告诉你译文「有多难改」 | ✅ v4.18.0 |

**一句话总结共同规律**：高手们都不满足于「AI 改完给你看」，而是围绕三件事做文章——
1. 让错误「看得见、归得类」（高亮 + 分类）；
2. 让校对「分阶段、可回退」（一校二校、修订留痕）；
3. 让重复劳动「零成本复用」（翻译记忆、术语一致性体检）。

### 1.2 BelinDoc 取经（2026-10）

朋友推荐的「AI 文档翻译」工具（belindoc.com）。它跟我们**不是一类**——它是「上传文档 → 全文翻译 → 保持格式导出」，我们是「译校助手」（校对已有译文 + 术语一致）。三点可取：

| BelinDoc 的做法 | 对我们有什么用 | 状态 |
|---|---|---|
| **格式保持 / 版式还原**（翻译完导回 Word） | 校对完导回原文档，改动以 Word 修订痕迹标出，逐条接受/拒绝 | ✅ v4.23.0（修订模式）|
| **多模型预设下拉**（GPT/Claude/Gemini/DeepSeek） | 24 家一键切换，选中即回填接口地址与模型名（含小米 MiMo）| ✅ v4.23.0 |
| **首页「效果演示」**（真实对比图） | 「使用指南」加示例 + 校对前后对比 | ✅ v4.25.2 |

**它的护城河缺口 = 我们的护城河**：它没有术语库、没有术语一致性体检、没有决策面板、没有校对流程，只"翻"不"校"，术语必然不统一——这正是我们的核心价值，别丢。

### 1.4 多人协作制度取经：伊里因科夫翻译工作流（2026-10）

**来源与致谢**：本轮演进方向参考了朋友提供的两份文件——`AGENT-EXECUTABLE.md`（「伊里因科夫翻译工作流 — Agent 执行规范」）及其通俗版 docx。来源标注：md 行5 frontmatter 与行810「整理自 `hoshF/ilyenkov-translation-workflow`，遵循 CC BY 4.0」；原仓库自述「把它当成方法论用，比当成开箱即用的软件用更合适」（docx 行219）。它回答的核心问题是「译完了，凭什么说它是对的」（docx 行46），把主观的「翻得好不好」变成客观的「谁审过、依据什么、改了哪」。**感谢这个项目贡献的创意与想法**——我们取其精华、按自己的节奏落地。
